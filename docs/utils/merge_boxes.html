utils.merge_boxes

Provides space aware grouping and clustering utilities for OCR text items.

This module is responsible for aggregating individual OCR words into coherent text lines, and subsequently grouping those lines into distinct speech bubbles or text blocks. It addresses complex layout challenges typical in vertical reading formats (e.g., mangas, webtoons), such as tightly packed or vertically interleaved dialogue columns.

Core features:

  1. Vertical Stream Detection: Uses a Union-Find algorithm to identify vertical columns of text. This acts as a geometric guard rail to prevent merging adjacent but physically distinct bubbles.
  2. Line Construction: Groups words horizontally while dynamically splitting them based on physical gaps and stream IDs.
  3. Bubble Clustering: Merges lines into bubbles using a best-match scoring system based on aggregate bounding box geometry, Intersection over Union (IoU), and containment metrics.
  4. Noise Filtering: Identifies and removes standalone single-character OCR artifacts before downstream processing (e.g., inpainting, translation).

 38# --- HELPER FUNCTIONS ---
 39def box_stats(box):
 40    # Force float64 to handle extremely long images (e.g., webtoons)
 41    xs = [float(p[0]) for p in box]
 42    ys = [float(p[1]) for p in box]
 43    x1, x2 = min(xs), max(xs)
 44    y1, y2 = min(ys), max(ys)
 45    return {
 46        "x1": x1, "x2": x2, "y1": y1, "y2": y2,
 47        "cx": (x1 + x2) / 2.0,
 48        "cy": (y1 + y2) / 2.0,
 49        "w": max(1.0, x2 - x1),
 50        "h": max(1.0, y2 - y1),
 51    }

 54def vertical_overlap(a, b):
 55    inter = max(0.0, min(a["y2"], b["y2"]) - max(a["y1"], b["y1"]))
 56    return inter / max(1.0, min(a["h"], b["h"]))

 59def same_line(a, b, y_tol=None):
 60    """
 61    Checks if two OCR items lie on the same text line.
 62
 63    Uses solely the distance between their Y-centers (cy) — without vertical_overlap.
 64
 65    Why vertical_overlap was removed:
 66    PaddleOCR often returns tall boxes (e.g., 60px) for a line spacing of ~28px,
 67    yielding ~53% overlap between adjacent lines. With overlap_min=0.35, this
 68    caused consecutive lines to merge via "chaining" — each new item was within
 69    y_tol of the previous one, dragging an entire vertical bubble into a single
 70    line, and subsequent x1-sorting reversed the correct reading order.
 71
 72    y_tol = 30% of the smaller box's height (previously 40%):
 73    - for h=60px: y_tol=18px  -> correctly separates lines spaced by ~22–28px
 74    - for h=30px: y_tol=9px   -> safely merges items on the exact same line
 75    """
 76    if y_tol is None:
 77        y_tol = max(5.0, 0.3 * min(a["h"], b["h"]))
 78    return abs(a["cy"] - b["cy"]) <= y_tol

 85# --- VERTICAL STREAMS DETECTION ---
 86#
 87# Problem being solved: When two different bubbles are close to each other on
 88# the X-axis and their text lines happen to fall at the exact same Y-height.
 89# No heuristic looking SOLELY at a single line can distinguish them if the
 90# horizontal gap between them is exceptionally small. Furthermore, with multiple
 91# columns of text interleaving on the Y-axis, comparing a new line only to the
 92# LAST added line of a bubble causes "drift", eventually gluing physically
 93# distinct bubbles together.
 94#
 95# VISUAL EXAMPLE OF THE "CLOSE GAP" PROBLEM:
 96#
 97#   Y=10:    [AN ORDER]          [EVEN IN A STATE]
 98#   Y=40:    [HAS BEEN]          [OF EMERGENCY]
 99#   Y=70:    [GIVEN TO THIS MAN]-[WE CANNOT]        <-- Danger Zone
100#
101# At Y=70, the left text line is wide, making the horizontal gap between
102# "MAN" and "WE" extremely narrow. A naive line-builder looking only at the
103# X-axis gap will mistakenly merge them into one horizontal line:
104# "GIVEN TO THIS MAN WE CANNOT".
105#
106# Solution: An independent, line-agnostic geometric signal - "do these two items
107# lie one below the other in roughly the same X column?" - calculated on individual
108# OCR words, bypassing line segmentation. This naturally mirrors the physical shape
109# of a speech bubble (a narrow, vertical column of text) and works perfectly
110# regardless of X-axis spacing.
111#
112# VISUAL EXAMPLE OF THE SOLUTION (Streams):
113#
114#      Stream 1                     Stream 2
115#     [AN ORDER]          !=    [EVEN IN A STATE]
116#         | (linked)                    | (linked)
117#     [HAS BEEN]                [OF EMERGENCY]
118#         | (linked)                    | (linked)
119#     [GIVEN TO THIS MAN]       [WE CANNOT]
120#
121# By grouping vertically first, "GIVEN..." is solidly anchored to Stream 1,
122# and "WE CANNOT" is anchored to Stream 2. Now, even if they share the exact
123# same Y=70 elevation with a tiny gap, the guard rail sees (Stream 1 != Stream 2)
124# and FORCES a horizontal split, keeping the text bubbles completely separate.
125#
126# This DOES NOT replace same_line / split_line_by_gap / group_lines_into_bubbles -
127# it is an additional guard rail used in both places: it forces a line split or
128# rejects a bubble match when two items have a strong (confirmed, >=2 items) but
129# DIFFERENT stream. Lack of evidence (a 1-item stream) is never treated as a
130# "definitely different bubbles" signal - only an actual, confirmed column is.

132class _UnionFind:
133    """
134    A lightweight Disjoint-Set (Union-Find) data structure with path compression.
135
136    Used internally to efficiently cluster individual OCR text items into connected
137    vertical streams (columns) by merging neighboring geometric components.
138    """
139    __slots__ = ("parent",)
140
141    def __init__(self, n):
142        """Initializes n independent disjoint sets."""
143        self.parent = list(range(n))
144
145    def find(self, x):
146        """
147        Finds the root representative of the set containing x.
148
149        Applies path compression during traversal to flatten the tree structure,
150        ensuring near constant time complexity [ O(α(n)) ] for future queries.
151        """
152        root = x
153        while self.parent[root] != root:
154            root = self.parent[root]
155        while self.parent[x] != root:
156            self.parent[x], x = root, self.parent[x]
157        return root
158
159    def union(self, a, b):
160        """Merges the disjoint sets containing elements a and b."""
161        ra, rb = self.find(a), self.find(b)
162        if ra != rb:
163            self.parent[ra] = rb

166def _x_overlap_ratio(a, b):
167    """
168    Calculates the horizontal (X-axis) overlap ratio between two bounding boxes.
169
170    The overlap is strictly calculated relative to the width of the *narrower* box.
171    This is a deliberate geometric choice: if a short word (e.g., "I") is perfectly
172    stacked above or below a wide word (e.g., "SOMETHING"), dividing by the smaller
173    width yields a 1.0 (100%) overlap. This allows robust detection of vertical
174    text columns even when line widths vary drastically.
175
176    :param a: Spatial stats dictionary for the first bounding box.
177    :param b: Spatial stats dictionary for the second bounding box.
178    :return: A float between 0.0 and 1.0 representing the overlap ratio.
179    """
180    inter = max(0.0, min(a["x2"], b["x2"]) - max(a["x1"], b["x1"]))
181    return inter / max(1.0, min(a["w"], b["w"]))

184def _likely_same_column(top, bottom,
185                        max_v_gap=_STREAM_MAX_V_GAP,
186                        min_x_overlap=_STREAM_MIN_X_OVERLAP,
187                        max_cx_drift=_STREAM_MAX_CX_DRIFT):
188    """
189    Determines if `bottom` (the lower item) appears to be a continuation of the
190    same text column as `top` (the upper item). Both arguments are stats dicts.
191    """
192    v_gap = bottom["y1"] - top["y2"]
193    if v_gap > max_v_gap:
194        return False
195    if v_gap < -min(top["h"], bottom["h"]) * 0.5:
196        # Too much vertical overlap - this is likely the same row, not two separate
197        # lines in a column. Not our concern here (same_line handles this).
198        return False
199    if _x_overlap_ratio(top, bottom) >= min_x_overlap:
200        return True
201    cx_drift = abs(top["cx"] - bottom["cx"])
202    return cx_drift <= max_cx_drift * max(top["w"], bottom["w"])

205def compute_vertical_streams(enriched_items, window=_STREAM_WINDOW):
206    """
207    Returns a dict mapping index in `enriched_items` -> stream_id (int) or None.
208
209    A stream_id is assigned only when an item has at least one confirmed neighbor
210    in the same column (stream size >= 2). Single, isolated items (e.g., the only
211    line in a small bubble, with nothing above/below in a similar X) get None -
212    lack of evidence is not evidence of a "different bubble", so such items
213    should not force any improper splits.
214    """
215    n = len(enriched_items)
216    if n == 0:
217        return {}
218
219    uf = _UnionFind(n)
220    order = sorted(range(n), key=lambda i: enriched_items[i]["stats"]["cy"])
221
222    for oi, i in enumerate(order):
223        a = enriched_items[i]["stats"]
224        for j in order[oi + 1: oi + 1 + window]:
225            b = enriched_items[j]["stats"]
226            top, bottom = (a, b) if a["cy"] <= b["cy"] else (b, a)
227            if bottom["y1"] - top["y2"] > _STREAM_MAX_V_GAP:
228                break  # Order is sorted by cy - it only gets further away from here
229            if _likely_same_column(top, bottom):
230                uf.union(i, j)
231
232    roots = [uf.find(i) for i in range(n)]
233    sizes = Counter(roots)
234    return {idx: (root if sizes[root] >= 2 else None) for idx, root in enumerate(roots)}

237def split_line_by_gap(line_items, gap_multiplier=3.0, image_width=None):
238    """
239    Splits a line into separate fragments if the horizontal gap between items is too large.
240    Prevents merging words from different bubbles that happen to share the same Y elevation.
241
242    VISUAL EXAMPLE: THE "IMAGE WIDTH CAP" PROBLEM
243
244    Imagine a wide canvas (e.g., image_width = 1250px). We have two completely
245    separate bubbles sharing the same Y-plane:
246
247    x=130          x=250            x=390              x=490
248      [THEN HOW]                         [TO STOP]
249      (avg_w: 120px)     <GAP 140px>     (avg_w: 100px)
250
251    Logic WITHOUT image_width cap:
252      - avg_w ~ 110px.
253      - max_gap = 110px * gap_multiplier (3.0) = 330px.
254      - Actual gap (140px) < max_gap (330px) -> MERGED x (Wrong!)
255
256    Logic WITH image_width cap (e.g., 5% of 1250px = 62.5px):
257      - max_gap = min(330, 62.5) = 62.5px.
258      - Actual gap (140px) > max_gap (62.5px) -> SPLIT - ok - (Correctly separated!)
259
260    :param line_items:      List of OCR items belonging to a single line.
261    :param gap_multiplier:  How many times wider than the average word the gap can be.
262    :param image_width:     Width of the scaled image in pixels. Caps the allowed gap.
263    :return: A list of lists — each sublist is a separate line fragment.
264    """
265    if len(line_items) <= 1:
266        return [line_items]
267
268    sorted_items = sorted(line_items, key=lambda x: x["stats"]["x1"])
269    avg_w = sum(i["stats"]["w"] for i in sorted_items) / len(sorted_items)
270    max_gap = avg_w * gap_multiplier
271
272    # Absolute cap: words inside a bubble are usually spaced by ~10–40 px;
273    # a gap >10% of the image width almost certainly indicates a different bubble.
274    if image_width and image_width > 0:
275        abs_cap = image_width * 0.05
276        max_gap = min(max_gap, abs_cap)
277
278    chunks = [[sorted_items[0]]]
279    for item in sorted_items[1:]:
280        prev = chunks[-1][-1]
281        gap = item["stats"]["x1"] - prev["stats"]["x2"]
282
283        # GUARD RAIL: if both items have a strong (confirmed, >=2 items) but
284        # DIFFERENT vertical stream (see compute_vertical_streams) - it is highly
285        # probable these are two different text columns / bubbles, even if the
286        # horizontal gap is smaller than max_gap. This handles the exact case of
287        # lines like "AN ORDER" + "EVEN IN A STATE": different bubbles, same Y row,
288        # small horizontal gap - the gap alone won't catch this.
289        prev_stream = prev.get("stream_id")
290        item_stream = item.get("stream_id")
291        different_confirmed_stream = (
292                prev_stream is not None
293                and item_stream is not None
294                and prev_stream != item_stream
295        )
296
297        if gap > max_gap or different_confirmed_stream:
298            chunks.append([item])
299        else:
300            chunks[-1].append(item)
301
302    return chunks

306def build_text_lines(items, image_width=None):
307    """
308    Group individual OCR text items into cohesive horizontal lines without altering the original source data.
309    Returns a list of dictionaries where each dictionary represents a consolidated text line.
310
311    After performing a rough layout grouping based on the Y-axis, each line is conditionally split
312    using `split_line_by_gap`. This spatial validation prevents accidentally merging words originating
313    from separate text bubbles that happen to share the same horizontal elevation.
314
315    :param image_width: Width of the scaled image in pixels. Passed down to `split_line_by_gap`.
316    """
317    if not items:
318        return []
319
320    # 1. Guarantee every unique input item possesses a designated, trackable identifier (ID)
321    for idx, item in enumerate(items):
322        if "id" not in item:
323            item["id"] = f"word_{idx}"
324
325    # 2. Extract space-aware sorting metrics for sorting (executed on a data copy to preserve pristine state of items)
326    enriched = []
327    for item in items:
328        stats = box_stats(item["box"])
329        enriched.append({**item, "stats": stats})
330
331    # 3. Perform a rough vertical top-to-bottom sort based on centroid coordinates
332    enriched.sort(key=lambda x: x["stats"]["cy"])
333
334    # 3b. Detect vertical streams (text columns) - an independent geometric signal
335    #     used later as a guard rail in split_line_by_gap (see compute_vertical_streams).
336    stream_ids = compute_vertical_streams(enriched)
337    for idx, item in enumerate(enriched):
338        item["stream_id"] = stream_ids.get(idx)
339
340    raw_lines = []
341    for item in enriched:
342        added = False
343        for line in raw_lines:
344            if same_line(item["stats"], line[-1]["stats"]):
345                line.append(item)
346                added = True
347                break
348        if not added:
349            raw_lines.append([item])
350
351    # 4. Partition each line via split_line_by_gap — acts as a patch for words spanning across distinct bubbles
352    #    that reside on an identical vertical Y plane.
353    lines = []
354    for raw_line in raw_lines:
355        raw_line.sort(key=lambda x: x["stats"]["x1"])
356        chunks = split_line_by_gap(raw_line, image_width=image_width)
357        lines.extend(chunks)
358
359    grouped_lines = []
360
361    # 5. Apply horizontal sorting and construct isolated data models for individual lines
362    for line_idx, line in enumerate(lines):
363        line.sort(key=lambda x: x["stats"]["x1"])
364
365        merged_text = " ".join([i["text"] for i in line])
366        word_ids = [i["id"] for i in line]
367        avg_score = sum(i["score"] for i in line) / len(line)
368
369        min_x = min(i["stats"]["x1"] for i in line)
370        min_y = min(i["stats"]["y1"] for i in line)
371        max_x = max(i["stats"]["x2"] for i in line)
372        max_y = max(i["stats"]["y2"] for i in line)
373
374        merged_box = [
375            [min_x, min_y], [max_x, min_y],
376            [max_x, max_y], [min_x, max_y]
377        ]
378
379        # Dominant stream_id of a row - majority of the votes of its component words.
380        # None if no word has a confirmed stream (no evidence -> no signal).
381        stream_counter = Counter(i["stream_id"] for i in line if i.get("stream_id") is not None)
382        line_stream_id = stream_counter.most_common(1)[0][0] if stream_counter else None
383
384        grouped_lines.append({
385            "line_id": f"line_{line_idx}",
386            "word_ids": word_ids,
387            "text": merged_text,
388            "score": avg_score,
389            "box": merged_box,
390            "stream_id": line_stream_id,
391        })
392
393    return grouped_lines

396def _group_stats(b_group):
397    """
398    Returns aggregate space-aware stats for an entire bubble group (all lines combined).
399
400    Using the WHOLE group bounding box instead of just the last line is the core fix
401    for the bubble_6/7/9 merging bug: when three interleaved columns of text share the
402    same Y range, comparing only to b_group[-1] causes "drift" — each new line from a
403    different column is close to the previous one, so they all end up in the same group.
404    Comparing to the aggregate box makes the accumulated X range visible and lets the
405    cx / x_overlap checks reject truly distinct columns.
406    """
407    all_points = []
408    for line in b_group:
409        all_points.extend(line["box"])
410    agg = box_stats(all_points)
411
412    # Median cx of individual lines — more robust than the aggregate centroid for
413    # groups where a single wide line would skew the center.
414    median_cx = median(box_stats(l["box"])["cx"] for l in b_group)
415    agg["median_cx"] = median_cx
416    return agg

419def _score_candidate(l_stats, b_stats, y_dist_mult, x_overlap_thresh):
420    """
421    Evaluates how well a line fits into a bubble group.
422
423    Returns a float score >= 0 if the line is a valid candidate (lower = better fit),
424    or None if any hard constraint is violated and the line must NOT join this group.
425
426    Hard constraints (return None):
427      - vertical gap too large
428      - x overlap ratio below threshold
429      - cx distance too large
430      - confirmed different vertical stream (stream_id guard rail)
431
432    Score (when all constraints pass):
433      Combination of normalized vertical gap and cx distance — lower means the line
434      is geometrically closer to this group's center.
435    """
436    vertical_gap = l_stats["y1"] - b_stats["y2"]
437
438    abs_gap_limit = 120.0
439    max_gap = min(abs_gap_limit, b_stats["h"] * y_dist_mult)
440    if vertical_gap >= max_gap:
441        return None
442
443    overlap_x = max(0.0, min(l_stats["x2"], b_stats["x2"]) - max(l_stats["x1"], b_stats["x1"]))
444
445    # X alignment check — two complementary metrics, take the higher one.
446    #
447    # VISUAL EXAMPLE OF X-ALIGNMENT METRICS (IoU vs Containment):
448    #
449    # CASE 1: Narrow word near a wide bubble (Slight X-overlap but different bubbles)
450    #
451    #           [ I ](w:15)
452    #               [ SOMETHING ELSE ENTIRELY ](w:200)
453    #
454    #   -> IoU is very low (~0.07). REJECTED. (Correct!)
455    #
456    # CASE 2: Narrow word genuinely inside a wide bubble group
457    #
458    #                     [  VR  ](w:30)
459    #           [ VERY WIDE BUBBLE GROUP BOX  ](w:200)
460    #
461    #   -> IoU is STILL very low (~0.15) -> WOULD BE FALSELY REJECTED!
462    #   -> Containment ratio (Overlap / Line_Width): 30/30 = 1.0 -> ACCEPTED. (Correct!)
463    #
464    # Containment is used only when the line is significantly narrower than the
465    # group (width ratio < 0.4). In all other cases, IoU is the primary metric.
466
467    iou_x = overlap_x / max(1.0, l_stats["w"] + b_stats["w"] - overlap_x)
468    containment_x = overlap_x / max(1.0, l_stats["w"])
469    containment_group = overlap_x / max(1.0, b_stats["w"])
470
471    # Use a more liberal containment metric when ANY side is significantly
472    # narrower than the other (ratio < 0.4). This handles two symmetric cases:
473    #   - narrow line ("VR") inside a wide group -> containment_x saves it
474    #   - wide line ("FINE DAY") trying to join a group anchored by a narrow word
475    #     ("A") → containment_group saves it
476    # The cx_dist guard below still rejects cross-bubble false positives.
477    narrow_line = l_stats["w"] < b_stats["w"] * 0.4
478    narrow_group = b_stats["w"] < l_stats["w"] * 0.4
479    if narrow_line or narrow_group:
480        x_overlap_ratio = max(iou_x, containment_x, containment_group)
481    else:
482        x_overlap_ratio = iou_x
483
484    if x_overlap_ratio <= x_overlap_thresh:
485        return None
486
487    cx_dist = abs(l_stats["cx"] - b_stats.get("median_cx", b_stats["cx"]))
488    max_cx_dist = (l_stats["w"] + b_stats["w"]) * 0.45
489    if cx_dist >= max_cx_dist:
490        return None
491
492    # Lower score = better fit; weight vertical proximity more than horizontal drift
493    score = (vertical_gap / max(1.0, max_gap)) * 0.6 + (cx_dist / max(1.0, max_cx_dist)) * 0.4
494    return score

497def group_lines_into_bubbles(grouped_lines, x_overlap_thresh=0.35, y_dist_mult=1.5, min_score=0.7):
498    """
499    Groups individual text lines into speech bubble clusters using spatial constraints.
500
501    VISUAL EXAMPLES OF THE LAYOUT PROBLEMS SOLVED:
502
503    Problem 1: Overlaping/mixed Columns (Solved by BEST-MATCH)
504      Group 1 (X:100)          Group 2 (X:300)
505      [HELLO]                  [WHAT ARE]
506      [THERE]                  [YOU DOING]
507                      [TODAY?] <-- Incoming line (X:280)
508
509      With FIRST-MATCH, [TODAY?] might pass the loose maximum-distance checks for
510      Group 1 and be swallowed incorrectly. BEST-MATCH scores both candidate groups
511      and correctly assigns it to Group 2 because the geometric distance is much smaller.
512
513    Problem 2: The "Drift" Effect (Solved by AGGREGATE GROUP STATS)
514      [LINE 1]
515         [LINE 2]
516            [LINE 3]
517                              [LINE 4] <-- Different bubble
518
519      If Group 1's bounds are based ONLY on the last appended line ([LINE 3]),
520      the horizontal gap to [LINE 4] looks dangerously small. By using AGGREGATE
521      STATS (a single bounding box wrapping Lines 1+2+3), the group's true center
522      (median_cx) stays safely anchored to the left, preventing the bubble from
523      "drifting" rightward and falsely swallowing Line 4.
524
525    Key improvements over the original implementation:
526
527    1. BEST-MATCH instead of FIRST-MATCH:
528       The original code appended each line to the first bubble group that passed all
529       checks. With overlapping columns (three bubbles sharing the same Y range), the
530       first passing group was often the wrong one. Now every candidate group is scored
531       and the line goes to the geometrically closest match.
532
533    2. AGGREGATE GROUP STATS instead of LAST-LINE STATS:
534       Spatial checks (vertical gap, x overlap, cx distance) are now computed against

239def split_line_by_gap(line_items, gap_multiplier=3.0, image_width=None):
240    """
241    Splits a line into separate fragments if the horizontal gap between items is too large.
242    Prevents merging words from different bubbles that happen to share the same Y elevation.
243
244    VISUAL EXAMPLE: THE "IMAGE WIDTH CAP" PROBLEM
245
246    Imagine a wide canvas (e.g., image_width = 1250px). We have two completely
247    separate bubbles sharing the same Y-plane:
248
249    x=130          x=250            x=390              x=490
250      [THEN HOW]                         [TO STOP]
251      (avg_w: 120px)     <GAP 140px>     (avg_w: 100px)
252
253    Logic WITHOUT image_width cap:
254      - avg_w ~ 110px.
255      - max_gap = 110px * gap_multiplier (3.0) = 330px.
256      - Actual gap (140px) < max_gap (330px) -> MERGED x (Wrong!)
257
258    Logic WITH image_width cap (e.g., 5% of 1250px = 62.5px):
259      - max_gap = min(330, 62.5) = 62.5px.
260      - Actual gap (140px) > max_gap (62.5px) -> SPLIT - ok - (Correctly separated!)
261
262    :param line_items:      List of OCR items belonging to a single line.
263    :param gap_multiplier:  How many times wider than the average word the gap can be.
264    :param image_width:     Width of the scaled image in pixels. Caps the allowed gap.
265    :return: A list of lists — each sublist is a separate line fragment.
266    """
267    if len(line_items) <= 1:
268        return [line_items]
269
270    sorted_items = sorted(line_items, key=lambda x: x["stats"]["x1"])
271    avg_w = sum(i["stats"]["w"] for i in sorted_items) / len(sorted_items)
272    max_gap = avg_w * gap_multiplier
273
274    # Absolute cap: words inside a bubble are usually spaced by ~10–40 px;
275    # a gap >10% of the image width almost certainly indicates a different bubble.
276    if image_width and image_width > 0:
277        abs_cap = image_width * 0.05
278        max_gap = min(max_gap, abs_cap)
279
280    chunks = [[sorted_items[0]]]
281    for item in sorted_items[1:]:
282        prev = chunks[-1][-1]
283        gap = item["stats"]["x1"] - prev["stats"]["x2"]
284
285        # GUARD RAIL: if both items have a strong (confirmed, >=2 items) but
286        # DIFFERENT vertical stream (see compute_vertical_streams) - it is highly
287        # probable these are two different text columns / bubbles, even if the
288        # horizontal gap is smaller than max_gap. This handles the exact case of
289        # lines like "AN ORDER" + "EVEN IN A STATE": different bubbles, same Y row,
290        # small horizontal gap - the gap alone won't catch this.
291        prev_stream = prev.get("stream_id")
292        item_stream = item.get("stream_id")
293        different_confirmed_stream = (
294                prev_stream is not None
295                and item_stream is not None
296                and prev_stream != item_stream
297        )
298
299        if gap > max_gap or different_confirmed_stream:
300            chunks.append([item])
301        else:
302            chunks[-1].append(item)
303
304    return chunks

VERTICAL STREAM GUARD RAIL: If the incoming line has a confirmed stream_id (set by compute_vertical_streams, meaning >=2 words stacked vertically in the same X column) AND the dominant stream_id of the candidate group is confirmed AND they differ — the line is forbidden from joining that group regardless of distance scores. This fires exactly when columns are close in X but geometrically distinct (the line_45 case).
